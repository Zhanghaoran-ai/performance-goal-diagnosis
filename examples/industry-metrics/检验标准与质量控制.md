# 行业指标库 - 检验标准与质量控制

> 本文档定义行业指标库的数据检验标准、质量控制流程和验收标准。

---

## 一、数据源权威性分级

### 1.1 五级权威性标准

| 星级 | 等级 | 说明 | 典型来源 | 可信度 |
|------|------|------|---------|--------|
| ⭐⭐⭐⭐⭐ | 非常权威 | 国际标准 / 国家强制标准 / 学术综述 | ISO、IEC、国家标准、PMC学术综述 | 95%+ |
| ⭐⭐⭐⭐ | 权威 | 专业机构报告 / 行业通用基准 / 头部企业实践 | ASQ、麦肯锡、Gartner、上市公司财报 | 85%+ |
| ⭐⭐⭐ | 较权威 | 单一机构调研 / 细分领域参考 | 行业博客、细分领域报告、咨询公司文章 | 70%+ |
| ⭐⭐ | 一般 | 经验估算 / 行业通用说法 | 行业经验、通用基准 | 50%+ |
| ⭐ | 参考 | 未经验证的估算 / 单一案例 | 单个企业数据、个人经验 | 30%+ |

### 1.2 数据源准入标准

| 用途 | 最低权威性要求 | 验证要求 |
|------|--------------|---------|
| 战略层指标基准值 | ⭐⭐⭐⭐ | 至少2个独立来源交叉验证 |
| 管理层指标基准值 | ⭐⭐⭐ | 至少1个权威来源 |
| 执行层指标基准值 | ⭐⭐ | 至少1个来源，标注"参考值" |
| 合理范围 | ⭐⭐⭐ | 与基准值来源一致 |

## 二、数据准确性检验

### 2.1 交叉验证规则

| 验证类型 | 说明 | 通过标准 |
|---------|------|---------|
| **多源交叉验证** | 用至少2个独立来源的数据进行对比 | 偏差 ≤ 10% |
| **历史趋势验证** | 与历史数据对比，检查变化趋势是否合理 | 年变化率 ≤ 30%（特殊行业除外） |
| **逻辑一致性验证** | 检查关联指标之间的逻辑关系是否合理 | 符合业务逻辑 |
| **极值检验** | 检查基准值是否在合理范围内 | 不超出行业常识范围 |

### 2.2 偏差预警机制

| 偏差范围 | 预警等级 | 处理方式 |
|---------|---------|---------|
| **< 10%** | 正常 | 直接更新 |
| **10% ~ 20%** | 黄色预警 | 行业专家审核后更新 |
| **20% ~ 50%** | 橙色预警 | 多方交叉验证，维护者+专家共同确认 |
| **> 50%** | 红色预警 | 暂停更新，深入调查原因 |

## 三、数据完整性检验

### 3.1 元数据完整性检查

每个指标必须包含以下元数据，缺一项即为不合格：

**战略层指标：**
- [ ] 指标名称
- [ ] 基准值
- [ ] 合理范围
- [ ] 数据来源
- [ ] 发布机构
- [ ] 数据截止时间
- [ ] 来源链接
- [ ] 权威性评分
- [ ] 稳定性分级
- [ ] 验证状态
- [ ] 详细说明

**管理层/执行层指标：**
- [ ] 指标名称
- [ ] 基准值
- [ ] 合理范围
- [ ] 对应上层指标
- [ ] 数据来源
- [ ] 数据截止时间
- [ ] 稳定性分级
- [ ] 详细说明

### 3.2 覆盖率检查

| 检查项 | 合格标准 |
|--------|---------|
| 行业覆盖率 | 每个行业都有完整的三层指标 |
| 层级覆盖率 | 战略层5-8个，管理层8-12个，执行层5-8个 |
| 元数据完整率 | 100%的指标包含所有必填元数据 |
| 已验证指标占比 | 战略层 ≥ 60%，管理层 ≥ 40% |

## 四、数据一致性检验

### 4.1 三层指标一致性

| 检查项 | 说明 | 合格标准 |
|--------|------|---------|
| **对应关系** | 每个管理层/执行层指标都有对应的上层指标 | 100%有对应 |
| **逻辑支撑** | 下层指标确实能支撑上层指标 | 符合业务逻辑 |
| **不重复** | 同层级指标之间没有明显重复 | 重复率 ≤ 10% |
| **不遗漏** | 上层指标的关键维度都有下层指标支撑 | 关键维度覆盖率 ≥ 80% |

### 4.2 跨行业一致性

| 检查项 | 说明 |
|--------|------|
| **同名指标定义一致** | 不同行业的同名指标（如OEE）定义和计算方法一致 |
| **基准值差异合理** | 不同行业的同类指标基准值差异有合理解释 |
| **元数据格式统一** | 所有行业的指标文件格式一致 |

## 五、质量控制流程

### 5.1 新增指标质检流程

```
1. 提交新增指标申请
   ↓
2. 检查元数据完整性（缺一项打回）
   ↓
3. 检查数据源权威性（低于准入标准打回）
   ↓
4. 交叉验证（无第二来源标注"待验证"）
   ↓
5. 行业专家审核
   ↓
6. 加入指标库，更新变更日志
```

### 5.2 更新指标质检流程

```
1. 提交更新申请（含新旧值对比）
   ↓
2. 计算偏差，触发预警机制
   ↓
3. 偏差 < 10% → 直接更新
   偏差 10-20% → 专家审核
   偏差 > 20% → 多方验证
   ↓
4. 更新元数据（特别是数据截止时间）
   ↓
5. 更新变更日志
```

### 5.3 定期质量审计

| 审计类型 | 频率 | 审计内容 | 输出物 |
|---------|------|---------|--------|
| **全面审计** | 每年1次 | 所有指标的元数据、准确性、一致性 | 年度质量报告 |
| **抽样审计** | 每季度1次 | 随机抽取20%的指标进行检查 | 季度审计报告 |
| **专项审计** | 触发式 | 用户反馈集中的行业/指标 | 专项整改报告 |

## 六、用户反馈处理

### 6.1 反馈渠道

| 渠道 | 说明 | 响应时间 |
|------|------|---------|
| **诊断报告反馈入口** | 在诊断报告中点击"指标不准"按钮 | 自动记录 |
| **邮件反馈** | 发送邮件到维护者邮箱 | 3个工作日内回复 |
| **Issue跟踪** | 在代码仓库提交Issue | 5个工作日内回复 |

### 6.2 反馈处理流程

```
1. 收到用户反馈
   ↓
2. 记录反馈内容（指标名称、问题描述、用户建议值）
   ↓
3. 核实反馈（查找最新数据，对比验证）
   ↓
4. 反馈属实？
   ├─ 是 → 更新指标，感谢用户，记录贡献者
   └─ 否 → 回复用户说明原因，提供数据来源
   ↓
5. 同一指标收到 ≥3 个类似反馈 → 触发即时更新
```

### 6.3 反馈统计指标

- 每月收到反馈数量
- 反馈处理率（目标：100%）
- 反馈属实率（目标：≥ 60%）
- 平均响应时间（目标：≤ 3个工作日）

## 七、质量评分体系

### 7.1 指标库整体质量评分

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| **元数据完整性** | 25% | 完整率 × 25 |
| **数据源权威性** | 25% | 平均星级 / 5 × 25 |
| **数据准确性** | 25% | 已验证指标占比 × 25 |
| **覆盖完整性** | 15% | 行业覆盖率 × 15 |
| **时效性** | 10% | 在有效期内的指标占比 × 10 |

### 7.2 质量等级

| 分数 | 等级 | 说明 |
|------|------|------|
| 90-100 | 优秀 | 可作为权威参考使用 |
| 75-89 | 良好 | 可作为主要参考，少量指标需验证 |
| 60-74 | 合格 | 可作为参考，建议结合其他数据源 |
| < 60 | 待改进 | 仅供初步参考，需要大量完善 |
