# 指标拆解合理性判定 Checklist

> v2.7 输出边界：指标必须作为独立节点。关系来源分为 `explicit`（输入显式配置）、`semantic_inference`（父目标/对齐目标限定范围后的四层语义候选）、`user_confirmed`（用户确认或改选）和 `data_gap`（证据不足、用户拒绝或待核实时不建确定边）。同一目标内的指标不自动互为父子；推断边必须展示置信度并允许确认、拒绝、改选和待核实，导出 JSON 后回读才能改变下一次诊断。

> 用于从语义层面判断目标与指标、上级指标与下级指标之间的关联性和承接关系是否合理。

---

## 一、关联性检查（30分）

### 1.1 直接关联性（10分）
- [ ] 下级指标名称中包含上级指标的核心关键词
- [ ] 下级指标的描述中明确提到对上级指标的支撑作用
- [ ] 指标之间有明确的因果关系，不是简单并列

**判定标准**：
- 10分：完全满足，关联性清晰直接
- 7分：基本满足，有关联但不够直接
- 4分：关联较弱，需要推导才能看出关系
- 0分：完全无关，上下级指标说的是两回事

### 1.2 维度一致性（10分）
- [ ] 上下级指标属于同一业务维度（如都是质量维度/效率维度/成本维度）
- [ ] 指标的计量单位逻辑一致（都是比率/都是绝对值/都是金额）
- [ ] 指标的时间周期匹配（都是月度/都是季度/都是年度）

**判定标准**：
- 10分：三个维度都一致
- 7分：两个维度一致
- 4分：一个维度一致
- 0分：完全不一致

### 1.3 范围匹配性（10分）
- [ ] 下级指标的覆盖范围不超过上级指标
- [ ] 所有下级指标加起来能够覆盖上级指标的主要方面
- [ ] 没有明显的遗漏或越界

**判定标准**：
- 10分：范围完全匹配，无遗漏无越界
- 7分：基本匹配，有少量遗漏
- 4分：部分匹配，有明显遗漏或越界
- 0分：范围严重不匹配

---

## 二、承接关系检查（30分）

### 2.1 因果承接（10分）
- [ ] 下级指标是上级指标的驱动因素（因→果关系清晰）
- [ ] 下级指标的改善能够直接导致上级指标的改善
- [ ] 因果方向正确，没有倒置

**判定标准**：
- 10分：因果关系清晰，方向正确
- 7分：有因果关系，但不够直接
- 4分：因果关系模糊，需要解释
- 0分：没有因果关系，或因果倒置

### 2.2 数学承接（10分）
- [ ] 上下级指标之间有明确的数学关系（加总/相乘/比例/公式）
- [ ] 下级指标的数值加总/换算后与上级指标逻辑一致
- [ ] 指标之间的比例关系合理

**判定标准**：
- 10分：数学关系明确且数值合理
- 7分：有数学关系但不够精确
- 4分：数学关系模糊
- 0分：没有数学关系

### 2.3 层级承接（10分）
- [ ] 指标粒度逐级细化（上级宏观，下级微观）
- [ ] 指标颗粒度与层级匹配（战略层→管理层→执行层）
- [ ] 没有越级或层级混乱

**判定标准**：
- 10分：层级清晰，粒度逐级细化
- 7分：基本合理，有少量粒度问题
- 4分：层级混乱，粒度不均匀
- 0分：完全没有层级概念

---

## 三、完整性检查（20分）

### 3.1 维度完整性（10分）
- [ ] 覆盖了上级目标的所有关键维度
- [ ] 没有重要维度的缺失
- [ ] 各维度之间相对均衡，没有明显偏重

**常见维度框架**：
- 平衡计分卡：财务/客户/内部流程/学习成长
- 质量管理：人/机/料/法/环
- 项目管理：范围/时间/成本/质量

**判定标准**：
- 10分：维度完整且均衡
- 7分：基本完整，有少量缺失
- 4分：明显缺失重要维度
- 0分：维度单一，严重不完整

### 3.2 逻辑闭环（10分）
- [ ] 指标之间形成完整的逻辑闭环
- [ ] 有输入指标、过程指标、结果指标
- [ ] 有正向指标也有反向/风险指标

**判定标准**：
- 10分：形成完整闭环，有进有出有监控
- 7分：基本闭环，缺少个别环节
- 4分：逻辑链条断裂
- 0分：完全没有闭环概念

---

## 四、可执行性检查（20分）

### 4.1 可衡量性（10分）
- [ ] 每个指标都有明确的定义和计算方法
- [ ] 数据来源清晰可获取
- [ ] 有明确的计量单位

**判定标准**：
- 10分：完全可衡量，定义清晰数据可得
- 7分：基本可衡量，有少量模糊点
- 4分：难以衡量，定义模糊数据难获取
- 0分：完全不可衡量，只是口号

### 4.2 可影响性（10分）
- [ ] 对应层级的人员能够直接影响该指标
- [ ] 指标的可控程度与层级匹配
- [ ] 不是"看得见摸不着"的指标

**判定标准**：
- 10分：完全可控，该层级人员能直接影响
- 7分：基本可控，有一定影响
- 4分：可控性弱，主要靠外部因素
- 0分：完全不可控，与该层级无关

---

## 五、总分与等级

| 分数段 | 等级 | 说明 |
|--------|------|------|
| 90-100 | 优秀 | 指标拆解非常合理，逻辑清晰，承接到位 |
| 75-89 | 良好 | 整体合理，有少量优化空间 |
| 60-74 | 合格 | 基本合理，有明显的改进空间 |
| 40-59 | 待改进 | 存在较多问题，需要系统性优化 |
| < 40 | 不合格 | 指标拆解混乱，建议重新设计 |

## 六、常见问题模式

### 问题模式 1：假拆解
**表现**：上下级指标只是换了个说法，本质是同一个东西，没有真正拆解。
**示例**：
- 上级：提升客户满意度
- 下级：提高客户满意程度

**判定**：关联性满分，但承接关系 0 分，因为没有真正拆解。

### 问题模式 2：错位拆解
**表现**：下级指标和上级指标有关联，但不是直接的承接关系，维度错位。
**示例**：
- 上级：提升营收（财务维度）
- 下级：提升员工满意度（学习成长维度）

**判定**：关联性弱，维度不一致。

### 问题模式 3：遗漏关键维度
**表现**：只覆盖了上级目标的部分方面，重要维度缺失。
**示例**：
- 上级：提升产品质量
- 下级：只有"降低不良率"，没有"提升一次合格率"、"减少客诉"等

**判定**：完整性得分低。

### 问题模式 4：粒度不均
**表现**：有的下级指标很宏观，有的很微观，粒度不均匀。
**示例**：
- 上级：提升运营效率
- 下级1：优化供应链管理（很宏观）
- 下级2：提升打印机打印速度（很微观）

**判定**：层级承接得分低。

### 问题模式 5：因果倒置
**表现**：把结果当原因，把原因当结果，因果方向反了。
**示例**：
- 上级：提升客户满意度
- 下级：增加复购率（复购率是满意度的结果，不是原因）

**判定**：因果承接 0 分。

## 七、自动诊断规则

### 可自动检测的模式

1. **关键词匹配**：检查上下级指标是否有共同关键词
2. **粒度检测**：根据指标名称长度、修饰词数量判断粒度
3. **维度分类**：基于关键词将指标分类到不同维度，检查维度覆盖
4. **因果词检测**：检测"提升→导致"、"降低→减少"等因果关系词
5. **数量检测**：检查下级指标数量是否合理（3-7个为宜）

### 需要人工判断的模式

1. 深层语义关联性
2. 复杂因果关系
3. 行业特定的指标逻辑
4. 业务场景的特殊性

---

## 八、使用说明

### 在诊断工具中使用

1. 自动检测可自动化的模式，给出初步评分
2. 对于不确定的部分，标注"待人工确认"
3. 生成 checklist 报告，列出各项得分和问题点
4. 给出改进建议，指向具体的问题模式

### 人工复核时使用

1. 按照 checklist 逐项检查
2. 对自动检测的结果进行校准
3. 补充自动检测无法覆盖的业务逻辑判断
4. 给出最终的合理性评分和改进建议

## 九、四层语义关联判断法（v2.5 新增）

> 用于判断"上级指标能否被下级指标真正支撑"，而非仅看指标名是否相似。
> 已封装为 `semantic_utils.SemanticAnalyzer.assess_relationship()`，供诊断与树视图复用。

### 核心思想

语义关联 = 由粗到细的四层判定，每层独立计分，最终综合分级：

```
第1层 词面相似  → 第2层 语义相似  → 第3层 因果方向  → 第4层 数值链路
  (复制嫌疑)       (换说法假拆解)    (子是否驱动父)     (数值是否闭合)
```

### 四层定义

| 层级 | 判定内容 | 方法 | 风险信号 |
|------|---------|------|---------|
| 1. 词面层 | 字符重叠 / Jaccard 相似度 + 包含关系 | `multi_dim_similarity` + 父子文本互含检测 | `fake_split`（岗位前缀复制） |
| 2. 语义层 | 分词 + 同义词映射后的语义相似 | `word_similarity`（jieba + HR 同义词词典） | `semantic_overlap`（换说法重复） |
| 3. 因果层 | 下级(因) → 上级(果) 方向判定 | `detect_causal_direction`（过程 vs 结果特征词） | `causal_reverse`（因果倒置） |
| 4. 数值链路层 | 下级目标值加总 vs 上级目标值 | 比值法：<0.5 或 >1.5 判定断裂 | `numeric_mismatch`（数值不闭合） |

### 综合计分规则

```
overall = 词面×0.15 + 语义×0.40 + 因果×0.25 + 数值×0.20
硬信号压级：因果倒置 → overall 封顶 0.2；假拆解 → overall 封顶 0.35
```

| 综合得分 | 关联等级 | 含义 |
|---------|---------|------|
| ≥0.75 | strong | 下级能良好支撑上级 |
| 0.50~0.74 | medium | 有关联但需关注 |
| 0.30~0.49 | weak | 关联弱，建议人工复核 |
| <0.30 | none | 基本无关，可能错位拆解 |

### 判定边界（重要）

1. **语义关联是"弱信号"**：判定"承接关系弱"只提示**需要人工复核**，不直接定罪。
2. **跨域关联例外**：如"员工敬业度"支撑"产品交付质量"，语义不相似但确有业务关联，需人工判断。
3. **数值链路仅在有数值时生效**：缺失目标值时跳过该层，不罚分、不误报。
4. **岗位前缀复制是最强的假拆解信号**：子指标名包含父指标名时，无论相似度如何均标记 `fake_split`。

### 典型证据示例

| 场景 | 上级 | 下级 | 四层判定结果 |
|------|------|------|-------------|
| 假拆解（复制） | 员工体验提升指数 | 员工关系专员执行-员工体验提升指数 | 词面互含 → `fake_split`，压级 weak |
| 数值链路断裂 | 研发需求交付率(95) | 下级加总(380) | 比值 400% → `numeric_mismatch`，weak |
| 正常承接 | 客户满意度 | 客户NPS净推荐值 | 语义同义映射，medium~strong |
| 无关指标 | 招聘完成率 | 系统可用性 | 词面/语义均低，none |
